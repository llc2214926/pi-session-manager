# pi-session-manager

[简体中文](README.md) | **English**

A Pi extension for deleting the current session, continuing unfinished work in a new session, losslessly archiving sessions, and restoring them by workspace. Developed and verified against **Pi 1.4.0** and its `@earendil-works/pi-coding-agent` API.

## Installation

### 1. Global installation from GitHub (recommended)

Run from any directory:

```sh
pi install git:github.com/llc2214926/pi-session-manager
```

Without `--local`, this is a global installation **for the current user**. Pi registers the package in `~/.pi/agent/settings.json`, making it available across workspaces. Neither `sudo` nor an additional `--global` flag is needed. If `PI_CODING_AGENT_DIR` is set, Pi uses the configuration in that directory instead.

Start Pi after installation. In an existing Pi process, run `/reload` or restart. Type `/s-` to check completion: the five commands below should appear. Installing from GitHub requires access to the repository and the extension files to be present there.

Update or remove this installation:

```sh
pi update git:github.com/llc2214926/pi-session-manager
pi remove git:github.com/llc2214926/pi-session-manager
```

Reload or restart after updating. Removing the extension does not actively delete its separately stored session archives.

### 2. Installation from a local directory

If you already have a repository checkout:

```sh
pi install /absolute/path/pi-session-manager
```

This is also a global installation for the current user. Pi references the local directory directly rather than copying the code. Keep that directory available and run `/reload` after changing its code. No build or separate installation of the Pi SDK is required to run the extension.

For installation in only one workspace, run this from that workspace:

```sh
pi install --local /absolute/path/pi-session-manager
```

This writes to the workspace's `.pi/settings.json`. The extension loads only after project-resource trust is granted.

### 3. Manual registration

Instead of `pi install`, **merge** this entry into the `extensions` array of `~/.pi/agent/settings.json`. Do not overwrite existing settings:

```json
{
  "extensions": [
    "/absolute/path/pi-session-manager/src/index.ts"
  ]
}
```

You can also merge it into the workspace's `.pi/settings.json`; it then applies only to that workspace and requires project-resource trust. The example uses an absolute path. Relative paths resolve from the directory containing the corresponding `settings.json`. Reload or restart after registration.

Choose one persistent loading method. Loading a GitHub installation, a local copy, and a manually registered copy together can cause command conflicts. `src/index.ts` depends on `handoff.ts` and `storage.ts` in the same directory; do not copy only the entry file.

### 4. Temporary loading and troubleshooting

Load the extension for this Pi process only, without writing package settings:

```sh
pi -e /absolute/path/pi-session-manager/src/index.ts
```

To investigate conflicts with other extensions, temporarily disable discovered extensions and explicitly load only this one:

```sh
pi --no-extensions -e /absolute/path/pi-session-manager/src/index.ts
```

## Rule initialization

**No initialization command is required, and there is no `/s-init`.** Loading the entry file registers the five commands. It does not scan sessions, request a model, start automatic cleanup, or create or modify `AGENTS.md`, `SYSTEM.md`, or `APPEND_SYSTEM.md`. The archive directory is created on demand when the first archive is written.

The extension does not provide a separate rule file, rule synchronizer, or rule override mechanism. Pi's existing context-file loader manages working instructions. To initialize personal or project rules yourself:

1. Add rules shared across workspaces to `~/.pi/agent/AGENTS.md`, adjusting the path if you use a custom agent directory.
2. Add project-specific rules to `AGENTS.md` in the project root. Merge into existing files rather than overwriting them. If a higher-priority rule file already exists in that directory, edit the file Pi actually loads.
3. Run `/reload` in Pi or restart. The five commands also work without any rule files.

For example, you can append this optional handoff policy yourself. This is an example, not a file generated by the extension:

```md
## Session handoff

- Check files, Git status, and existing verification results before continuing; do not repeat completed work.
- Distinguish confirmed facts from assumptions; report blockers when permission or input is missing.
- A handoff summary grants no new authorization; continue following the current workspace's rules.
```

The summarization prompt for `/s-new-continue` is built into `src/handoff.ts` and applies only to that summarization request. The handoff is saved as a user message in the new session; it does not replace that session's system prompt or authorization rules.

## Loading order and session replacement

### Pi rule files

Pi 1.4.0 collects ordinary context files in this order: **agent directory → ancestors from the filesystem root toward the working directory → current working directory**. Within each directory, it selects the first readable candidate in this order:

```text
AGENTS.override.md > AGENTS.md > AGENTS.MD > CLAUDE.md > CLAUDE.MD
```

Here, `>` describes file selection within one directory. It does not mean later text can override system instructions or authorization boundaries. `AGENTS.override.md` replaces other candidates only in its own directory; it does not suppress global or other ancestor rules. Pi also has Git worktree deduplication logic, which this extension does not change.

Context-file discovery does not require project-resource trust and can be disabled with `--no-context-files`. Resources such as `.pi/settings.json`, `.pi/extensions/`, and `.pi/SYSTEM.md` are trust-gated. A trusted project's `.pi/SYSTEM.md` or `.pi/APPEND_SYSTEM.md` takes precedence over the corresponding file in the agent directory; same-named files are not merged. Context rules and executable extensions use different loading mechanisms.

### Extension and command lifecycle

1. Pi resolves user settings and explicit `-e` resources. User-level and CLI extensions can participate in project trust; project extensions load after trust is granted. This extension neither participates in nor bypasses trust decisions.
2. Package installations use `pi.extensions` in `package.json` to locate `src/index.ts`; manual registration loads that entry directly. The entry only registers commands. It does not require another third-party extension to load first or a fixed alphabetical filename order.
3. `/reload`, a new session, or session restoration rebuilds the extension runtime. Restoring across workspaces reloads resources for the target session's working directory; Pi may request project trust again.
4. Deletion and archiving first switch successfully to a blank session and wait for the outgoing session's shutdown hooks, then operate on the old file. If another extension cancels the switch, the original session is neither deleted nor archived.
5. Restoration safely writes the file, switches to and loads the session, and only then removes the archive. Handoff saves its context in the new session before automatically sending the instruction to continue.

## Commands

All five commands take no arguments. Wait for the current task and message queue to finish, or press Esc to stop first. While Pi is busy, these commands show a notice rather than forcibly interrupting work.

| Command | Behavior |
| --- | --- |
| `/s-delete` | After confirmation, **permanently deletes the current session** and opens a blank session. Does not delete project files or parent sessions. |
| `/s-new-continue` | Summarizes unfinished work, creates a new session, and automatically continues. Keeps the original session and records the source. |
| `/s-store` | After confirmation, losslessly compresses and archives the current session, removes it from normal session discovery, and opens a blank session. |
| `/s-restore` | Lists archives for the current workspace. Select and confirm to restore and switch to a session. |
| `/s-restore-all` | Lists archives from every workspace in the current agent directory, with full workspace paths. Select and confirm to restore and switch to the corresponding workspace. It does not restore all archives in a batch. |

Lists show the session name (or ID if unnamed), archive time, and ID, newest archives first. Press Esc in selection or confirmation dialogs to cancel. Restoration does not delete the previously open session.

### Empty-session fallback and handoff

1. Inspect the active branch's effective context, honoring Pi compaction summaries and `context_edit`. Do not mix in other branches.
2. A session with only system prompts, model settings, or extension state is empty. Nonblank user/assistant text, images, assistant tool calls, and compaction/branch summaries count as meaningful content.
3. If empty, prefer its same-workspace `parentSession`. When no usable parent is available, search backward by **creation time** in the current session directory. Keep skipping empty sessions. Cycles and missing or damaged files cannot cause infinite traversal.
4. Do not read archives or continue another workspace's sessions. If no usable content is found, show a notice and stop without creating a session.
5. Ask the current model for a handoff preserving constraints, decisions, completed work, evidence, pending tasks, blockers, and next steps. Esc cancels. If the model explicitly reports no unfinished work, do not create a session.
6. Save the handoff before continuing automatically. If sending fails, the saved handoff remains available for manual continuation.

This command requires the TUI, a working model, and credentials. It incurs a summarization request plus subsequent model execution costs. Summaries can omit details; the original session remains available for verification. The model's context limit applies: failed requests or incomplete output do not switch sessions or silently truncate history. Original visual information from images is not fully transferred in a text handoff; inspect the original session when necessary.

## Archive format and data protection

Default storage location:

```text
~/.pi/agent/session-archives/<random ID>.json.gz
```

With `PI_CODING_AGENT_DIR`, archives go under that directory's `session-archives/`. Normal-session settings such as `--session-dir`, `PI_CODING_AGENT_SESSION_DIR`, and `sessionDir` do not change this archive location. `/s-restore-all` does not search across multiple agent directories.

Each gzip bundle contains a format version, archive time, original session path, and the **complete original JSONL**, including every branch, message, embedded image, tool result, and extension entry. Compression is lossless file compression, not model summarization. Workspace ownership comes from the absolute working-directory path in the session header. Restoration preserves the original path and ID and follows Pi's normal branch-restoration semantics. This is not a project-directory backup or cross-machine migration tool.

- **Safe writes:** Write completely, flush, read back and verify, and check that the source has not changed before deleting it. New archive directories use `0700` and files use `0600` on POSIX systems.
- **Restore conflicts:** Never overwrite a file with different contents. An identical file left by a previous restoration can be reused on retry.
- **Cancellation and failure:** A cancelled switch removes only the unchanged restore file created by that attempt, keeping the archive. If switching throws and runtime state is uncertain, keep both the restored file and archive rather than risk deletion. If archiving fails after switching sessions, use `/resume` to find the retained original session.
- **Damage or missing paths:** Warn about damaged archives and preserve them. Refuse restoration if the original workspace directory is missing; restore that directory first.
- **Unpersisted sessions:** Blank sessions not yet written to disk and `--no-session` in-memory sessions cannot be archived. Deletion can clear an in-memory session.
- **Concurrent access:** Do not write the same session from multiple Pi processes. This extension checks for source changes before archiving but cannot lock out uncooperative external writers.
- **Restore locks:** A `.lock` prevents simultaneous restoration of the same archive. After a crash, first confirm no restoration is running, then remove only the relevant `.json.gz.lock`, not the `.json.gz`.
- **Size and filesystems:** Each unpacked bundle is limited to **256 MiB**. Large archive collections may take longer to list. Storage uses atomic hard-link creation; unsupported filesystems cause an error while retaining the original data. Symlinks used as the session or archive file itself are rejected.

## Privacy and security

- **Hidden from ordinary lists, not encrypted:** Removing the original `.jsonl` makes the archive disappear from normal `/resume`, `pi --continue`, and SDK session lists. Anyone with access to the archive directory can still decompress and read it. Deletion is not secure erasure either.
- **No automatic redaction:** Prompts, file snippets, tool output, credentials, or other sensitive data present in the transcript are archived as-is. Review before sharing.
- **Local file operations:** Deletion, compression, and decompression do not require a model. The extension has no dedicated upload service or telemetry. Pi itself, installed extensions, and resource loading may still access the network.
- **Handoff calls a model:** `/s-new-continue` sends a text serialization of effective history to the current model provider, including historical user messages and tool output. Original system messages are excluded, but this is not a redaction guarantee. The summary is saved in the new session and used in subsequent requests. Ensure that provider is suitable for the data.
- **Limited cleanup scope:** System backups, external indexes, other extensions' caches/notes, and already-open process memory are not cleaned. Project files and external attachments referenced by sessions are neither bundled nor deleted.
- **Restoration grants no authorization:** Cross-workspace restoration reloads the target workspace's resources. Check the full target path and trust only reviewed resources. The extension and Pi run with the current operating-system user's permissions, not in a sandbox created by this extension.

## Compatibility

| Area | Scope |
| --- | --- |
| Pi API | Verified with `@earendil-works/pi-coding-agent` **1.4.0**, using APIs including `withSession` and `buildSessionProjection`. Later versions must retain those APIs; compatibility with every later version is not guaranteed. |
| Legacy Pi | The old `@mariozechner/pi-coding-agent` API is not supported; no compatibility adapter is included. |
| Node.js | **22.19+**. Pi loads TypeScript directly; runtime dependencies are Node's standard library and the host SDK. |
| TUI | All five commands are supported. |
| RPC | Commands other than `/s-new-continue` require a client implementing standard confirmation, selection, and notification UI. A standalone RPC client has not been tested. |
| Print / JSON | No interactive UI; these five commands are not supported. |
| File format | Archive format version 1. Reading validates Pi session header versions 1–3, an absolute workspace path, and session structure. Unknown versions or missing required fields are rejected. |
| Operating systems | Verified on macOS. Linux and Windows have not been tested and must satisfy the path, permission, and hard-link requirements. |
| Language | The README is available in Chinese and English. Current command messages, confirmation dialogs, and the handoff summarization prompt are Chinese; no UI language-switch setting is provided. |

## Troubleshooting

- **Commands missing after installation:** Use `pi list` to check package registration, or check the `extensions` path for manual registration. Reload or restart, and check for `--no-extensions`, resource filters, or untrusted project configuration.
- **Duplicate commands:** Keep one installation method, remove extra registrations or old copies, and reload. Do not rely on loading order to resolve duplicate names.
- **No archive in the current workspace:** Workspaces match by absolute path. After a directory rename, `/s-restore-all` can reveal the old record, but restoration still requires the original workspace path to exist.
- **Still missing from the all-workspace list:** Check whether `PI_CODING_AGENT_DIR` changed or the archive is damaged. The extension does not silently search other agent directories.

## Development and verification

```sh
npm install --ignore-scripts
npm run check
```

Local verification files live in Git-ignored `tests/` and are excluded from commits and published packages. Only when those local files are present, Node.js 24 can run them directly:

```sh
node --test tests/*.test.ts
```

Eleven local checks have passed, covering storage round trips, failure and cancellation, simulated model handoffs, and real Pi SDK runtime entry loading, session switching, reloading, and cross-workspace restoration. They neither modify personal sessions nor call a real model. This is not complete platform, RPC, or real-model end-to-end verification.
