# pi-session-manager

**简体中文** | [English](README.en.md)

Pi 会话管理扩展：删除当前会话或从列表选择删除、接手未完成任务、无损压缩归档，以及按工作区恢复会话。当前版本针对 **Pi 1.4.0** 的 `@earendil-works/pi-coding-agent` API 开发和验证。

## 安装

### 1. GitHub 全局安装（推荐）

在任意目录运行：

```sh
pi install git:github.com/llc2214926/pi-session-manager
```

不加 `--local` 时就是当前用户的全局安装，Pi 将包登记到 `~/.pi/agent/settings.json`，供各工作区使用；不需要 `sudo` 或额外的 `--global`。如果设置了 `PI_CODING_AGENT_DIR`，则使用该目录下的配置。

安装后启动 Pi；已经打开的 Pi 执行 `/reload` 或重启。输入 `/s-` 检查命令补全，应该看到下文的四个命令。使用 GitHub 源需要能访问仓库，且仓库中已包含扩展文件。

更新或卸载该安装：

```sh
pi update git:github.com/llc2214926/pi-session-manager
pi remove git:github.com/llc2214926/pi-session-manager
```

更新后同样需要 `/reload` 或重启。卸载扩展不会主动清除独立保存的会话归档。

### 2. 本地目录安装

已有仓库检出目录时：

```sh
pi install /absolute/path/pi-session-manager
```

这也是当前用户的全局安装。Pi 直接引用本地目录，不会复制一份代码；目录必须保留，代码变化后执行 `/reload`。运行扩展无需构建，也无需先为它安装一份独立的 Pi SDK。

只想在某个工作区使用时，在该工作区运行：

```sh
pi install --local /absolute/path/pi-session-manager
```

这会写入该工作区的 `.pi/settings.json`，需要授予项目资源信任后才加载。

### 3. 手动注册

不使用 `pi install` 时，可将以下条目**合并**到 `~/.pi/agent/settings.json` 的 `extensions` 数组，不要覆盖已有配置：

```json
{
  "extensions": [
    "/absolute/path/pi-session-manager/src/index.ts"
  ]
}
```

也可合并到工作区 `.pi/settings.json`，但只对该工作区生效，并受项目资源信任控制。示例使用绝对路径；相对路径以对应 `settings.json` 所在目录为基准。手动注册后执行 `/reload` 或重启。

只选一种持久加载方式，避免同时加载 GitHub 安装、本地副本和手动注册造成命令冲突。`src/index.ts` 依赖同目录的 `handoff.ts` 与 `storage.ts`，不要仅复制入口文件。

### 4. 临时加载与排查

只为本次 Pi 进程加载，不写入包配置：

```sh
pi -e /absolute/path/pi-session-manager/src/index.ts
```

排查与其他扩展的冲突时，可临时禁用自动发现的扩展，仅显式加载本扩展：

```sh
pi --no-extensions -e /absolute/path/pi-session-manager/src/index.ts
```

## 规则初始化

**本扩展无需初始化命令，也没有 `/s-init`。** 加载入口后即注册四个命令，不会扫描会话、请求模型、启动自动清理任务，或创建/修改 `AGENTS.md`、`SYSTEM.md`、`APPEND_SYSTEM.md`。归档目录在首次写入归档时按需创建。

扩展本身不提供独立的规则文件、规则同步器或规则覆盖机制。工作规则由 Pi 原有的上下文文件加载机制负责。如果需要初始化个人或项目规则：

1. 所有工作区共用的规则，手动添加到 `~/.pi/agent/AGENTS.md`（自定义 agent 目录时相应替换路径）。
2. 项目专用规则，手动添加到项目根目录的 `AGENTS.md`。有现有文件时合并内容，不要覆盖；若同目录已有更优先的规则文件，编辑实际被加载的那一份。
3. 在 Pi 中执行 `/reload` 或重启。没有规则文件也不影响这四个命令的使用。

例如，可以自行追加以下交接约定；这只是可选示例，不是扩展自动生成的文件：

```md
## 会话交接

- 接手任务前核对文件、Git 状态与已有验证结果，不重复已完成工作。
- 区分已确认结论和待核实信息；缺少权限或输入时明确报告阻塞。
- 交接摘要不构成新的授权，继续遵守当前工作区规则。
```

`/s-new-continue` 的摘要提示词内置于 `src/handoff.ts`，只用于该次摘要请求。新会话中保存的是用户消息形式的交接内容，不会替换目标会话的系统提示或授权规则。

## 加载顺序与会话切换

### Pi 规则文件

Pi 1.4.0 的普通上下文文件按以下顺序收集：**agent 目录 → 从文件系统根目录到当前工作目录的各级祖先 → 当前工作目录**。同一目录只选第一个可读取的候选文件，优先级为：

```text
AGENTS.override.md > AGENTS.md > AGENTS.MD > CLAUDE.md > CLAUDE.MD
```

这里的 `>` 表示同目录的文件选择顺序，不代表后加载的文本可以覆盖系统指令或授权边界。`AGENTS.override.md` 只替代同目录的其他候选，不会屏蔽全局或其他祖先目录的规则。Pi 另有 Git worktree 去重逻辑；本扩展不改写它。

上下文文件发现不依赖项目资源信任；`--no-context-files` 可禁用。`.pi/settings.json`、`.pi/extensions/`、`.pi/SYSTEM.md` 等受项目资源信任控制。受信任的项目 `.pi/SYSTEM.md` / `.pi/APPEND_SYSTEM.md` 优先于 agent 目录中对应的同名文件，而不是将同名文件合并。上下文规则与可执行扩展是两种不同的加载机制。

### 扩展及命令生命周期

1. Pi 解析用户配置和显式 `-e` 资源；用户级与命令行扩展可参与项目信任阶段。项目扩展在信任通过后加载。本扩展不参与或绕过信任决策。
2. 包安装使用 `package.json` 中的 `pi.extensions` 找到 `src/index.ts`；手动注册则直接加载入口。入口仅注册命令，不依赖其他第三方扩展先加载，也不要求固定文件名字母顺序。
3. `/reload`、新建会话或恢复会话会重建扩展运行时。跨工作区恢复使用目标会话的工作目录重新加载对应资源，Pi 可能再次要求项目资源信任。
4. 删除或归档当前会话时，先成功切换到空白会话，等待旧会话 shutdown 钩子完成，再操作旧文件。切换被其他扩展取消时，不删除或归档原会话。列表中删除或归档其他会话不会切换当前会话。
5. 恢复先安全写回文件，再切换并加载会话，成功后才移除归档；续接先将交接写入新会话，再自动发送继续指令。

## 命令

`/s-delete`、`/s-store` 与 `/s-restore` 支持下表的参数，`/s-new-continue` 不接受参数。执行前请等待任务和消息队列结束，或先按 Esc 停止；忙碌时命令只提示，不强行中断任务。

| 命令 | 行为 |
| --- | --- |
| `/s-delete` | 确认后**永久删除当前会话**，进入空白新会话。不会删除项目文件，也不删除父会话。 |
| `/s-delete -ls` | 列出当前工作区的普通会话；上下选择、回车请求删除，每次均需确认，删除后刷新并回到列表。 |
| `/s-delete -ls -all` | 列出全部工作区的普通会话，每项标注完整工作区路径；逐个确认删除，不是一次删除全部。 |
| `/s-new-continue` | 生成未完成任务的交接摘要，创建新会话并自动继续。原会话保留，新会话记录来源。 |
| `/s-store` | 确认后将当前会话无损压缩归档，从普通会话目录移除，进入空白新会话。 |
| `/s-store -ls` | 列出当前工作区的普通会话；上下选择、回车请求归档，每次均需确认，归档后刷新并回到列表。 |
| `/s-store -ls -all` | 列出全部工作区的普通会话，每项标注完整工作区路径；逐个确认归档，归档后继续留在列表。 |
| `/s-restore` | 列出当前工作区归档，选择并确认后恢复、切换到该会话。 |
| `/s-restore -all` | 列出当前 agent 目录中的全部工作区归档，每项标注完整工作区路径；选择并确认后恢复、切换到对应工作区。不是批量恢复全部归档。 |

`/s-restore -all` 与 `/s-restore --all` 等价，替代原独立命令 `/s-restore-all`；旧命令不再注册。

恢复列表按归档时间倒序，显示名称（未命名时显示 ID）、时间和 ID。选择或确认界面按 Esc 可取消。恢复不删除原先打开的会话。

### 列表删除与归档

`/s-delete` 与 `/s-store` 共用参数解析、会话列表和确认流程，仅最终操作不同：删除不可撤销；归档会先无损压缩并校验，再移除原文件，可用 `/s-restore` 恢复。

- 两个命令中 `-l`、`-ls` 与 `--ls` 等价，`-all` 与 `--all` 等价，也可混用；例如 `/s-delete -l -all` 或 `/s-store --ls --all`。`-all` 必须搭配列表参数，未知参数只提示用法，不执行操作。
- 按最近修改时间倒序，显示名称（未命名时显示首条消息或 ID）、时间、ID，并标记当前会话。列表只包含已落盘的普通会话，不包含归档或尚未保存的空白/内存会话。
- 当前工作区列表读取当前会话目录，并按工作区路径过滤。全部列表合并当前 agent 目录的默认会话库与当前会话目录（包含自定义 `--session-dir`），按文件路径去重；不会扫描磁盘上其他任意自定义目录或其他 agent 目录。
- 删除或归档其他会话不切换工作区或当前会话；操作标记为“当前会话”的条目时，先切换到同工作区空白会话，再删除或归档旧文件，并在新运行时继续显示列表。
- 取消确认、操作成功或文件操作失败都会回到刷新后的列表。列表清空后仍显示退出选项；在列表按 Esc 或选择“退出列表”才结束。
- 每次确认显示会话和完整工作区/文件路径，提示删除或归档的影响。非当前会话在确认期间被修改时拒绝操作；请勿操作仍在其他 Pi 进程中打开的会话。

### 空会话回溯与任务交接

1. 检查当前分支的有效上下文，沿用 Pi 对压缩摘要及 `context_edit` 的处理，不混入其他分支。
2. 只有系统提示、模型设置或扩展状态，没有实质对话的会话视为空。非空用户/助手文本、图片、助手工具调用及压缩/分支摘要视为有效内容。
3. 若为空，优先查找同工作区的 `parentSession`；没有可用父会话时，在当前会话目录中按**创建时间**向前查找。反复跳过空会话，遇到循环、缺失或损坏文件不会无限回溯。
4. 不读取归档，也不接手其他工作区的会话。一直找不到内容时提示并结束，不创建新会话。
5. 使用当前模型生成交接，保留约束、决定、已完成工作、证据、待办、阻塞和下一步。Esc 可取消。如果模型明确判定没有未完成任务，也不会新建会话。
6. 先保存交接，再自动继续；若发送失败，已保存的交接仍可手动继续。

此命令需要 TUI、可用模型和凭据，会产生一次摘要调用及后续执行的模型费用。摘要可能遗漏细节，原会话保留可核对。摘要受模型上下文限制；请求失败或输出不完整时不切换，也不静默裁掉历史。图片的原始视觉信息不会随文本交接完整迁移，必要时需要回看原会话。

## 归档格式与数据保护

默认存储位置：

```text
~/.pi/agent/session-archives/<随机 ID>.json.gz
```

设置 `PI_CODING_AGENT_DIR` 后使用该目录下的 `session-archives/`。普通会话的 `--session-dir`、`PI_CODING_AGENT_SESSION_DIR` 或 `sessionDir` 设置不会改变此归档位置。`/s-restore -all` 不会跨多个 agent 目录搜索。

每个 gzip 包包含格式版本、归档时间、原始会话路径及**完整原始 JSONL**，包括所有分支、消息、内嵌图片、工具结果和扩展条目。这里的压缩是无损文件压缩，不是模型摘要。归档按会话头中的工作区绝对路径归属；恢复保留原路径、ID，采用 Pi 普通恢复的分支语义，不是项目目录备份或跨机器迁移工具。

- **写入安全**：完整写入、刷盘、读回校验，并确认原文件未改变后，才删除原文件。POSIX 上新归档目录权限为 `0700`，文件为 `0600`。
- **恢复冲突**：不覆盖已有不同内容的文件。若相同文件已由上次恢复写入，可以重试。
- **取消与失败**：取消切换会清除本次写入且未改变的恢复文件，归档保留。切换抛错、状态不明时保留恢复文件与归档，避免误删。若归档失败但会话已经切换，可用 `/resume` 找回仍保留的原会话。
- **损坏或缺失**：损坏归档会显示警告并保留。原工作区目录不存在时拒绝恢复，应先恢复工作区目录。
- **未落盘会话**：空白且未落盘的会话、`--no-session` 内存会话不归档；删除命令可以清空内存会话。
- **并发**：勿让多个 Pi 进程同时写同一会话。本扩展能检查归档前文件变化，但无法锁住不配合的外部进程。
- **恢复锁**：同一归档使用 `.lock` 防止重复恢复。进程崩溃遗留锁时，确认没有恢复操作运行后，仅删除相应 `.json.gz.lock`，不要删除 `.json.gz`。
- **大小与文件系统**：单包解压后上限为 **256 MiB**；归档量大时列表加载可能较慢。存储使用原子硬链接创建文件，不支持硬链接的文件系统会报错并保留原数据；会话文件和归档文件本身的符号链接会被拒绝。

## 隐私与安全

- **普通列表隐藏，不是加密**：归档后原 `.jsonl` 被移除，正常 `/resume`、`pi --continue` 和 SDK 会话列表不再发现它；但能访问归档目录的人仍可解压读取内容。删除也不是安全擦除。
- **不自动脱敏**：会话中出现的提示词、文件片段、工具输出、凭据或其他敏感数据都会原样进入归档。对外分享前自行审查。
- **本地文件操作**：删除、压缩和解压不需要模型，扩展没有自建上传服务或遥测；Pi 本身、已安装扩展或资源加载仍可能联网。
- **续接需要模型调用**：`/s-new-continue` 将有效历史的文本序列化结果发送到当前模型提供方，包括历史中的用户消息和工具输出。它不附带原始 system 消息，但这不是脱敏保证。摘要写入新会话并用于后续请求；请确认提供方适合处理这些数据。
- **清理范围有限**：系统备份、外部索引、其他扩展的缓存/笔记、已打开进程的内存不清理。项目文件和会话引用的外部附件不打包、不删除。
- **恢复不是授权**：跨工作区恢复会重新加载目标工作区资源。确认完整目标路径，只信任已审查的资源；扩展与 Pi 以当前操作系统用户权限运行，不构成沙箱。

## 常见问题

- **安装后找不到命令**：先用 `pi list` 检查包登记；手动注册则检查 `extensions` 路径。执行 `/reload` 或重启，并确认未被 `--no-extensions`、资源过滤或项目不信任状态禁用。
- **出现重复命令**：保留一种安装方式，移除多余配置或旧副本，再重载；不要依赖加载顺序解决重名。
- **当前工作区看不到归档**：工作区按绝对路径匹配；目录改名后可用 `/s-restore -all` 查到旧路径记录，但恢复仍要求原工作区路径存在。
- **全部列表仍找不到归档**：确认是否更改了 `PI_CODING_AGENT_DIR`，以及归档包是否损坏；扩展不会静默跨 agent 目录搜索。

```sh
npm install --ignore-scripts
npm run check
```

本地验证文件放在被 Git 忽略的 `tests/`，不进入提交和发布包。仅在这些本地文件存在时，Node.js 24 可直接运行：

```sh
node --test tests/*.test.ts
```

本地验证覆盖存储往返、失败与取消、模拟模型交接、列表删除/归档的参数、范围与连续操作，以及真实 Pi SDK 运行时的入口加载、切换、重载与跨工作区恢复；不操作个人真实会话，也不调用真实模型。这不是完整平台、RPC 或真实模型端到端验证。
